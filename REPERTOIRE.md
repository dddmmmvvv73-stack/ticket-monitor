# Репертуар: постоянная база проектов

Реализовано 11.11.2026. «Репертуар → Проекты» — рабочая база артистов / программ;
«Работа → Проекты» — подготовка конкретных гастролей. Это разные записи с явными связями.

## Работа с базой

- **Моя база** показывает все сохранённые карточки из `my_projects.json`, включая проекты без афиши.
  Избранное — признак карточки; снятие звезды и очистка профиля её не удаляют.
- **Найти в афише** — поиск среди собранных мероприятий без общих фильтров рынка.
  Карточку можно сохранить в свою базу или начать заполнять.
- **+ Добавить проект** создаёт карточку вручную, даже если артиста нет у билетных операторов.
  Совпавший нормализованный ключ открывает существующую карточку, не создаёт копию.
- Поиск по названию, описанию, контакту и телефону; формат, сотрудничество, избранное /
  незаполненные поля; порядок по названию / обновлению. Фильтры рынка на базу не действуют.
- Старые входы «Гастролирует» и «Избранное» сохранены. У избранных есть счётчик изменений афиши.

## Карточка

**Профиль:** описание, формат, состав, гонорар и условия текстом, контакты, ссылки, оценка,
заметки, фотографии и райдеры. Название можно изменить; прежние ключи афиши остаются.
Другие написания можно связать через «Названия в афише».

**Афиша:** прежние текущие даты, архив и изменения относительно сохранённого снимка.
Окно выступления, продажи, назначение организаторов и разметка используют прежние функции.

**Аналитика:** маршрут / карта, заполняемость, цены, площадки, «Где не были» и официальный сайт.
Собираются даты всех связанных названий карточки. Диапазон «С / По» общий для афиши и аналитики
данной карточки, хранится только в состоянии интерфейса; по умолчанию — все даты.
Раздел официального сайта показывает полную сверку, независимо от выбранного диапазона.

**Связанные работы:** переговоры, подборы городов, туры финмодели и рабочие проекты.
Можно связать существующую запись, создать новую, перейти в неё и вернуться в карточку.
Базовые гонорар, процент сверху и состав копируются при создании расчёта.
Связывание существующей записи её экономику не меняет. Последующая правка карточки не
пересчитывает согласованные условия конкретного тура.
Прежнее одностороннее обновление гонорара из воронки в карточку сохранено.

Общая шапка рынка в этом пространстве скрыта. Используются обычные шрифты, таблицы,
кнопки, формы, меню и цвета сайта. Обложка компактная. У карточки свой адрес:
`#projects:card:<постоянный id>:profile|dates|analysis|work`.

## Данные и защита сохранения

Главные пользовательские данные — **`~/tm-server/config`**, а не папка разработки.
Выкладка передаёт код через Git; пользовательский `config/` из разработки туда не копируется.

`config/my_projects.json` и `config/project_media/` по-прежнему приватные, исключены из Git,
входят в существующие резервные копии. Существующие id, ключи, профили, оценки,
снимки изменений, настройки официальных сайтов и файлы сохраняются.

Дополнения записи карточки:

| Поле | Значение |
|---|---|
| `rev` | версия записи, увеличивается после правки и восстановления |
| `saved` | явно сохранена пользователем |
| `profile.format` | формат, в том числе у проекта без афиши |
| `connections.lists / tours / work` | массивы id связанных подборов, туров и рабочих проектов |
| `profile.riders[].kind` | `technical / hospitality / other`; старые файлы читаются как `other` |

- Запись карточек: межпроцессная и межпоточная блокировка на всё чтение → изменение → запись;
  API и восстановление журнала используют тот же замок.
- JSON пишется в уникальный временный файл с `fsync`, затем атомарно заменяется.
- Профиль сохраняется с ожидаемой версией. Устаревшая форма получает HTTP 409;
  её данные остаются в форме. «Перечитать и сравнить» подставляет свежие неизменённые поля,
  сохраняет введённые пользователем изменения и показывает пересечения перед повторным сохранением.
- Окно закрывается после успешного ответа сервера. Черновик формы сохраняется в браузере,
  отдельно для вкладок; после перезагрузки его можно восстановить или удалить.
  При выходе с изменённой формой есть предупреждение. Черновик ещё не является серверной копией.
- С этой версии фотографии имеют новые имена при замене; прежние файлы остаются.
  Удаление / замена райдера тоже сохраняет прежний файл. Журнал может вернуть рабочую ссылку.
  Это не восстанавливает бинарные версии, удалённые до внедрения: для них нужны прежние копии.
- Копии `db.offsite` пропускают служебные `.tmp` и `.lock`, сохраняя все пользовательские файлы.

## Перенос существующих связей и старых номеров строк

Перед изменением живых данных — приватная контрольная копия всей `config/` в
`~/tm-server/data/manual-backups/`.

`myprojects.connect_existing()` — предварительный просмотр, без записи.
`myprojects.connect_existing(write=True)` — добавляет только однозначные связи:
нормализованный проект афиши у подбора, проект экономики у тура, существующие id воронки.
Профили, контакты, файлы, суммы и пользовательские названия не переписывает; повторный запуск ничего не добавляет.
Неоднозначные записи связываются вручную.

`planning.repair_row_ids()` — одноразовое исправление повторных id строк старых туров.
Сохраняет все строки, порядок и поля, меняет только повторные / пустые номера.
Исходник оставляет в `config/history/planning-before-row-ids-*.json`.
Сервер больше не принимает тур с повторными номерами; новые id генерируются с большим случайным суффиксом.

## Код и проверка

- `Design/prototype/project-workspace.js/.css` — база, карточка, локальные фильтры, связи, файлы и черновики.
- `index.html` — интеграция с существующими `pjPage`, `anPage`, редактором, сохранением, адресами и переходами.
- `competitors/myprojects.py`, `market_api.py`, `journal.py`, `storage.py` — запись, версии, файлы, восстановление.
- `competitors/planning.py` — проверка уникальности и исправление прежних id строк.
- `tests/check_project_workspace_server.py` — конфликты форм, потоки и процессы, постоянные карточки,
  перенос связей без потери профиля, атомарная запись, файлы / журнал, старые строки и резервные копии.
- Регрессия: `node --test tests/*.test.js`, проверки процессов v2, подбора, расходов туров и файлов рабочих проектов.
- Браузер — отдельная копия на 5051. Тестовые карточки, файлы и ответы парсера не переносятся на рабочий сайт.
