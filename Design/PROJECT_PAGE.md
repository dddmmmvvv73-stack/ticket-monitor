> на проекте **AdrenalinHouse**. Документ — чтобы перенести вид на все проекты, не потеряв решений.

## 1. Как включить для всех проектов

1. В `index.html`: `var PJ_NEW_ALL = false` → **`true`**. Сейчас новый вид — только у названий, подходящих под
   `PJ_NEW_RE` (`/adrenalin\s*house/i`); остальные проекты — на старой странице `mShowcaseDetail`.
2. **Убрать тестовые изменения:** `PJ_DEMO_CHG` и `pjDemoDiff()` (ненастоящая лента «Изменения» у AdrenalinHouse) и
   строку `var demo = …` в `pjPage` (тогда `df = fav ? myDiff(rec) : null`), метку `.pj-demo`.
3. Проверить (Playwright, разделы 7–8): проект без дат, без продаж, без организаторов, с одной датой, с 40+ датами,
   местный проект, проект с площадкой прямого сбора, телефон 320–390 px — без горизонтальной прокрутки.
4. Старую страницу (`mShowcaseDetail`, `myNotesCard`, `myChangesCard`) удалить только после того, как пользователь примет
   новый вид на нескольких проектах.

## 2. Структура страницы (сверху вниз)

### 2.1. Шапка (`.pj-hero`)
- **Во всю ширину области страницы** (выходит за поля `.view`: 32 px, на телефоне 16 px) и **до самой верхней панели
  сайта** (`margin-top: -28px` / `-20px`, только если шапка — первый элемент). Без скруглений.
- Фон: загруженное фото (`background-size: cover`) с тёмным градиентом слева направо; без фото — тёмный радиальный
  градиент. **Положение фона по вертикали** — своё у проекта (`cover_y`, 0–100 %, по умолчанию 30 % — головы не
  обрезаются); меняется только из окна «Редактировать» → «Положение» (перетаскивание, стрелки ↑↓, «Готово» / «Отмена»).
- **Левый верхний угол:** круглая кнопка-галочка «назад» (без стрелки и подписи), стиль — как «Сменить фон».
- **Правый верхний угол:** «В избранное» (звезда; в избранном — жёлтая) и «Загрузить / Сменить фон». На телефоне —
  только значки (подписи скрыты, `aria-label` есть). Кнопки «Положение» в шапке **нет** (решение пользователя).
- **Аватар** — круг 168 px (телефон 104 px); без фото — инициалы. Клик — загрузить фото. Обрезка — **квадрат по центру**
  (вариант «подгонка: портрет сверху, широкое — с размытыми полями» пользователь отклонил).
- Название (Onest 600, 48 px), подзаголовок (если заполнен), **теги: формат · сфера · жанр + тип (гастроль / местное)**.
- **Ряд кнопок:** «Редактировать» (белая, с текстом) → круглые значки: Организаторы (с числом), Контакты, Официальный
  сайт, ВКонтакте, Instagram, Telegram. Значок соцсети: заполнено — ссылка; пусто — полупрозрачный пунктирный, открывает
  «Редактировать» сразу на этом поле.

### 2.2. Основная колонка — список
- Заголовок **«Мероприятия»** (без названия проекта — оно уже трижды на странице). В режимах — «Архив», «Изменения».
- Справа от заголовка — **склеенные значки** в рамке **той же ширины и скругления, что кнопка цены** (148 px, 6 px) —
  правые края совпадают: **Архив | (Изменения) | Аналитика**.
  - «Изменения» есть **только у избранного** и появляется с анимацией (`.appear`); пока лента не открыта — синий кружок
    с числом изменений.
  - «Аналитика» — на страницу маршрута (`data-proute`, раздел «Гастролирует»).
  - Переключение режимов **не сдвигает экран** (`window.scrollY` сохраняется).
- **Строка под заголовком** (`.pj-sum`, крупные цифры + серый текст) — появляется только когда нужна:
  период из шапки — «**ноябрь 2026** · **10** из 34 · Все даты»; лента изменений — «с **2 окт** · **2** новые · **1** снята ·
  **2** цены · **1** прошло · Просмотрено». Ссылки в ней — `.pj-plain` (тёмные, подчёркнутые), **не синие**.
- **Период — из шапки сайта** («30 дней», «90 дней», «Сезон», «Даты» — месяц или диапазон; `inPeriod`). Отдельных
  фильтров на странице нет.
- **Строка даты** (`pjRow`, сетка 4 колонки): жанр (капслок) + название · крупное число дня + день недели (капслок) и
  «месяц год» · город (капслок) + площадка · справа **кнопка «от … ₽»** (`.pj-price`, 148 px) и под ней **полоса
  заполняемости ровно по её ширине** (0–100 %, без подписи; процент и источник — в подсказке; нет данных — пунктир).
- Первые 8 строк (`PJ_ROWS`) и «Показать все · N дат».
- Прошедшие даты — **только в режиме «Архив»** (не подмешиваются в конец списка). Итог справа: «Событие прошло» /
  «Снято до даты».
- **Лента «Изменения»** (`pjChangesFeed`) — тот же вид строк: слева тип изменения цветом («Новая дата · новый город» —
  зелёный, «Снята до даты» — красный, «Цена изменилась», «Прошла»), справа — цена или «было → стало».

### 2.3. Правая колонка (`.pj-aside`, 340 px; ≤ 1100 px — под списком)
- **Описание** — заголовок = название проекта, текст свёрнут до 5 строк, «Развернуть текст»; пусто — «Добавить описание».
- **«О проекте»**: Тип (гастроль / местное + почему), Состав на выезде, Продаётся (Кассир / Яндекс — сколько дат),
  Наши площадки (если есть), Заметка, **Архив** («N прошедших дат →» — включает режим «Архив»).
- **Убрано по решению пользователя:** «Тур в цифрах» (города, цены, заполняемость — есть в «Аналитике»), список
  «Площадки» (перенесён на страницу маршрута — `mRouteVenues`), отдельный блок «Что изменилось» (стал режимом списка).

## 2а. Страница «Аналитика» (`anPage`, вход — значок «Аналитика» на странице проекта)
Тот же включатель `pjNew` (у остальных — старая страница маршрута `mProjectDetail`).
- **Шапка — та же, что у страницы проекта, по позициям до пикселя** (`an-hero-m`, классы `pj-hero` / `pj-hero-in`): ‹ назад
  (туда, откуда пришли: «Гастролирует» или страница проекта — `S.m.anFrom`); справа вверху «В избранное» и **«Проект»**;
  аватар 168 px; название; на месте подзаголовка — **«Аналитика»**; на месте тегов — пилюля **с периодом тура**; на месте
  ряда кнопок — **«Где не были»** (белая, как «Редактировать») и **значки разделов**: Маршрут, Заполняемость, Цены, Площадки
  (выбранный — белый). Справа — **компактные «стеклянные» плитки** 2×2 (города · даты с мини-столбиками по месяцам · цены ·
  заполняемость с полоской): правый край — по кнопке «Проект», низ — по ряду кнопок. Без фото фон — схема России с
  маршрутом (`anRouteBg`). Раздел «Организаторы» убран (решение пользователя). На странице проекта справа вверху вместо
  «Сменить фон» — **«Аналитика»** (фон меняется в окне «Редактировать»).
- **Разделы — по одному** (`AN_TABS`, `S.m.anTab`; кнопки — в шапке): Где не были · Маршрут · Заполняемость · Цены ·
  Площадки. Переключение не сдвигает экран.
  - **Маршрут** — «Лента | Карта» (`S.m.anMap`): точки цветом заполняемости (от 75 % — зелёный, 40–75 % — синий,
    ниже 40 % — красный, нет данных — серый; `AN_GOOD`, `AN_LOW`); точка — окно даты.
    **Карта — OpenStreetMap** (Leaflet 1.9.4 с cdnjs и `market-regions.js` грузятся только при открытии; Яндекс Карты
    отклонены — бесплатно нельзя на закрытом сайте). Слои (`AN_LAYERS`, `S.m.anLayers`): **Тур** — номера остановок цветом
    заполняемости, размер — вместимость, стрелки направления, клик — окно даты (несколько дат в городе — список);
    **По пути**; **Архив**; **Организаторы** — цвет остановок по организатору с легендой; **Конкуренты** — красный круг,
    сколько мероприятий того же формата в ±7 дней; **Области** — закраска по числу дат проекта за сезон (афиша + архив).
    **Отрезки:** гастроли идут день за днём — если между соседними датами 2 и более свободных дня (`AN_BREAK_FREE_DAYS`),
    это перерыв: маршрут режется (`anLegs`), линии и стрелок между отрезками нет. **Ползунок «Где тур в день»** шагает по
    датам тура (не по дням календаря), перерывы перепрыгивает: жёлтая точка — на городе выбранной даты, подсвечена её
    остановка, после перерыва — подпись «после перерыва N дней»; по умолчанию — ближайшая дата от сегодня. Области: `Design/prototype/market-regions.js` — Natural Earth 1:10m admin-1 (общественное
    достояние), упрощены, `MREG.city` — область каждого из 98 городов.
  - **Заполняемость по городам** — «По маршруту | Лучшие | Худшие» (`S.m.anSort`); строка — город и площадка, дата,
    мест, полоса, %, вал; окно даты по клику. **Первые 3** (`AN_FEW`), «Показать все · N» / «Скрыть». Блоки «Лучше
    всего / Хуже всего» убраны.
  - **Цены по городам** — диапазоны «от–до» на общей шкале (без подписи шкалы), первые 3, «Показать все» / «Скрыть».
  - **Организаторы по регионам** — кто, сколько дат, города; «без организатора — N дат».
  - **Площадки тура** (`mRouteVenues(l, 8)`) и **Где его нет** (`mCandTable`) — без рамок карточек (`.an-legacy`).
- Убрано: «Карточка проекта», 4 карточки цифр, блок «Продажи» со старым текстом, «Архив», «Все даты». Переключатели
  «гастроль / местное» (`tourBox`) — в окне «Редактировать» страницы проекта (`pjTourHtml`), сохраняются сразу.
- Тест: если настоящих цифр заполняемости меньше трёх, у AdrenalinHouse подставляются тестовые (`anFills`, метка
  «тестовые цифры заполняемости») — убрать вместе с `PJ_DEMO_CHG`.

## 2б. Оценка проекта — шестиугольник (radar), 09.10
- **Где правится:** только [`prototype/project-rating.js`](prototype/project-rating.js) → `PT_CONFIG`: 6 осей (Известность,
  Широта аудитории, Самопродажа, Отклик на рекламу, Потенциал роста, Ядро фанатов), подписи уровней 0–3 (нет / низкий /
  средний / высокий), **6 эталонов** и **порог «между»** (`between`). Компоненты страницы их не дублируют.
- **Тип не выбирается вручную:** `ptTypeOf` — ближайший эталон по евклидову расстоянию; если второй ближе первого меньше
  чем на `between` — «между «X» и «Y»». Рисунок — `ptRadar` (чистый SVG: 3 кольца, оси, номера на вершинах, закрашенный
  многоугольник, прошлая оценка — пунктиром; цвета от `currentColor` и `--pt-accent` — светлый и тёмный фон).
- **Где видно:** значок-миниатюра в шапке проекта (живой шестиугольник; без оценки — значок-контур) → окно «Оценка
  проекта»: слева шестиугольник, тип, дата, легенда; справа 6 переключателей 0–3 с подписями и подсказкой оси — тип и
  шестиугольник обновляются сразу при нажатии, «Сохранить оценку» — когда отмечены все 6 осей. «О проекте» — строка
  «Оценка» (миниатюра + тип). Список «Проекты» — столбец «Оценка» (миниатюра + тип) и фильтр «Оценка» (по типу,
  «Не оценён»).
- **Хранение:** `my_projects.json` (вне git) → `rating: {s: [6], at}`, прошлые — в `rating_hist` (до 50; повтор той же
  оценки историю не растит). Сервер — `myprojects.apply_op` «rating» (6 целых 0–3, иначе отказ); прототип — `myApply`.
- **Тест:** `node --test` → `tests/project-rating.test.js` (эталоны определяются сами собой, «между» по порогу, кривой
  профиль отклоняется, рисунок).

## 3. Окна (`pjDialog` — нативный `<dialog>`, Esc и клик мимо закрывают)

### 3.1. Окно даты (`pjOpenDate` / `pjDateHtml`) — вместо правой карточки на этой странице
- Заголовок окна скрыт (`sr-only`), сверху справа — **карандаш** (то же редактирование мероприятия: прямой сбор —
  `openEditor`, рынок — `mEditForm`) и крестик.
- Блоки через тонкие разделители: дата + **город и площадка** · заполняемость крупно («занято X из Y · свободно Z» и
  полоса) · Цены / Вал / Выручка · **Организатор** (пусто, если нет; «вписать / изменить»; пометка «вручную») и «В афише с»
  · ссылки на кассы **в стиле фильтров** (`.fbtn`: «ЯНДЕКС АФИША ↗», «КАССИР ↗», «VLADIMIRKONCERT ↗»).
- Внизу **одна кнопка «Продажи →»**: окно расширяется, справа выезжает панель (`pjdSalesToggle`) — **«Динамика продаж»**
  (график по снимкам, продано, возвраты) и **«Распоясовка»** (зал по рядам с ценами, `hallRows`); прямой сбор — из
  файлов (`factHtml`, `salesInDrawer`, `paceHtml`, `ROWS`), рынок — с сервера `/api/sales/detail`. Стрелка → / ←.
- **Убрано по решению пользователя:** тип площадки, «мест в зале», пояснение под полосой, предупреждение «продажи
  завышены (вопрос 27)», повтор жанра и названия, заголовок «Город · дата», кнопки «Закрыть» и «Продажи и зал по рядам».

### 3.2. «Редактировать» (`pjEditHtml` / `pjSave`)
Фото артиста и фон (Загрузить / Заменить / **Положение** — только у фона / Убрать), подзаголовок, описание, состав на
выезде, контакт, телефон, официальный сайт, гонорар, ВКонтакте, Instagram, Telegram, райдеры, другие ссылки, ещё
контакты, заметка; ниже формы — **«Разметка»** (`pjTourHtml`: тип проекта, артист целиком, тип площадки ближайшей даты —
сохраняется сразу, клики передаются в `mMarkProject` / `mMarkArtist` / `mMarkVenue`). Ссылки нормализуются (`pjUrl`): `vk.com/x` → `https://vk.com/x`, `@name` у Telegram / Instagram →
полный адрес. Загрузка фото обновляет только превью — несохранённые поля не теряются.

### 3.3. «Организаторы» (`pjOrgsHtml`)
В центре — фото артиста (или инициалы), вокруг «плавают» пилюли организаторов с числом дат (положение — от названия
проекта, одинаковое при каждом открытии; `prefers-reduced-motion` — без движения); ниже список: кто, сколько дат,
какие города. Кнопка **«+ Назначить организатора»** (`pjOrgAssignHtml`): имя с подсказками (`datalist` из известных
организаторов) + даты галочками по городам, «Все даты», «Только без организатора», «Снять все».

### 3.4. «Контакты» (`pjContactsHtml`)
Контакт, телефон (`tel:`), официальный сайт, ВКонтакте, Instagram, Telegram, гонорар, райдеры, ссылки, ещё контакты;
«Изменить» → окно «Редактировать».

## 4. Данные и честность цифр
- **Заполняемость даты** (`pjFill`): площадка прямого сбора — её схема без брони (`fill(d)`); рынок — сводка продаж
  (`mSalesFill(e.sales)`). Нет данных — пунктирная полоса. «Занято» ≠ «продано» (TICKET_PLATFORMS.md, правило 1) —
  пояснение в подсказке, не на экране.
- **Организатор**: строка «Организатор мероприятия» Кассира; вписанный вручную важнее (правка `org`).
- **Изменения** (`myDiff`): снимок будущих дат при добавлении в избранное / «Просмотрено» — `[дата, город, площадка,
  цена от, цена до]`; сравнение по «дата + город + площадка»: новые, снятые до даты, цена, прошедшие. Не видно:
  перенос (= снята + новая), продажи, смена организатора и названия.
- **Площадка в названии**: у дат ОрелКонцерта приписки «г. Орел» и даты убираются при сборе (`clean_title`).

## 7. Правила, которые пользователь задал явно (не возвращать)
- Меньше «мусора»: не повторять название проекта; пояснения — в подсказки, не на экран.
- Синие ссылки в тексте не использовать (`.pj-plain`); ссылки на кассы — в стиле фильтров.
- Миниатюры-значки вместо кнопок с текстом там, где смысл понятен (организаторы, контакты, соцсети, архив, аналитика,
  изменения); подсказка и `aria-label` — обязательно.
- Симметрия: пара значков = ширина и скругление кнопки цены; полоса заполняемости = ширина кнопки цены.
- Аналитика (цифры тура, площадки, маршрут) — на отдельной странице «Аналитика», не на странице проекта.
