## 1. Как включить для всех проектов

1. В `index.html`: `var PJ_NEW_ALL = false` → **`true`**. Сейчас новый вид обеих страниц — только у названий, подходящих
   под `PJ_NEW_RE` (`/adrenalin\s*house/i`); остальные — на старых `mShowcaseDetail` (проект) и `mProjectDetail` (маршрут).
2. **Убрать всё тестовое** (помечено «ТЕСТ» / жёлтой меткой): `PJ_DEMO_CHG` и `pjDemoDiff()` (лента «Изменения»), строку
   `var demo = …` в `pjPage` (→ `df = fav ? myDiff(rec) : null`), тестовые проценты в `anFills` (ветка `demo`), тестовые залы
   в `anFlipTile` (ветка `demo`), метку `.pj-demo`.
3. Проверить (раздел 9): проект без дат, без продаж, без организаторов, без оценки, с одной датой, с 40+ датами, местный
   проект, проект с площадкой прямого сбора, проект с фото и без; 1440 / 1024 / 390 / 320 px — без горизонтальной прокрутки.
4. Старые страницы (`mShowcaseDetail`, `myNotesCard`, `myChangesCard`, старый `mProjectDetail`) удалить только после того,
   как пользователь примет новый вид на нескольких проектах.

## 2. Страница «Проект» (`pjPage`)

### 2.1. Шапка (`.pj-hero`)
- **Во всю ширину области страницы** (выходит за поля `.view`: 32 px, на телефоне 16 px) и **до самой верхней панели
  сайта** (`margin-top: -28px` / `-20px`, если шапка — первый элемент). Без скруглений. Высота 300 px.
- Фон: загруженное фото (`cover`) с тёмным градиентом слева направо; без фото — тёмный радиальный градиент.
  **Положение фона по вертикали** — своё у проекта (`cover_y`, 0–100 %, по умолчанию 30 %); меняется **только** в окне
  «Редактировать» → «Положение» (перетаскивание, стрелки ↑↓, «Готово» / «Отмена»).
- **Левый верхний угол:** круглая кнопка-галочка «назад» (без стрелки и подписи), «стеклянная».
- **Правый верхний угол:** «В избранное» (звезда; в избранном — жёлтая) и **«Аналитика»** (на страницу «Аналитика»).
  Кнопки «Сменить фон» в шапке **нет** — фон меняется в «Редактировать». На телефоне — только значки.
- **Аватар** — круг 168 px (телефон 104 px); без фото — инициалы. Клик — загрузить фото. Обрезка — **квадрат по центру**
  (вариант «подгонка: портрет сверху, широкое — с размытыми полями» пользователь отклонил).
- Название (Onest 600, 48 px), подзаголовок (если заполнен), **теги: формат · сфера · жанр + тип (гастроль / местное)**.
- **Ряд кнопок:** «Редактировать» (белая, с текстом) → круглые «стеклянные» значки: **Организаторы** (без числа),
  **Контакты**, **Оценка** (живая миниатюра шестиугольника; без оценки — значок-контур), **Официальный сайт**,
  **ВКонтакте**, **Instagram**, **Telegram**. Соцсеть: заполнено — ссылка; пусто — полупрозрачный пунктирный значок,
  открывает «Редактировать» сразу на этом поле.

### 2.2. Основная колонка — список
- Заголовок **«Мероприятия»** (Onest 600, 30 px; без названия проекта). В режимах — «Архив», «Изменения».
- Справа от заголовка — **склеенные значки** в рамке **той же ширины и скругления, что кнопка цены** (148 px, 6 px),
  правые края совпадают: **Архив | (Изменения) | Аналитика**. «Изменения» есть **только у избранного** и появляется с
  анимацией (`.appear`); пока лента не открыта — синий кружок с числом. Переключение **не сдвигает экран**.
- **Строка под заголовком** (`.pj-sum`, крупные цифры + серый текст) — только когда нужна: период из шапки —
  «**ноябрь 2026** · **10** из 34 · Все даты»; лента изменений — «с **2 окт** · **2** новые · **1** снята · **2** цены ·
  **1** прошло · Просмотрено». Ссылки — `.pj-plain` (тёмные, подчёркнутые), **не синие**.
- **Период — из шапки сайта** («30 дней», «90 дней», «Сезон», «Даты» — месяц или диапазон; `inPeriod`).
- **Строка даты** (`pjRow`, сетка 4 колонки): жанр (капслок) + название · крупное число дня + день недели (капслок) и
  «месяц год» · город (капслок) + площадка · справа **кнопка «от … ₽»** (`.pj-price`, 148 px) и под ней **полоса
  заполняемости ровно по её ширине** (0–100 %, без подписи; процент и источник — в подсказке; нет данных — пунктир).
  Клик — **окно даты** (раздел 4.1). Первые 8 строк (`PJ_ROWS`) и «Показать все · N дат».
- Прошедшие даты — **только в режиме «Архив»**. Итог справа: «Событие прошло» / «Снято до даты».
- **Лента «Изменения»** (`pjChangesFeed`) — тот же вид строк: слева тип цветом («Новая дата · новый город» — зелёный,
  «Снята до даты» — красный, «Цена изменилась», «Прошла»), справа — цена или «было → стало».

### 2.3. Правая колонка (`.pj-aside`, 340 px; ≤ 1100 px — под списком)
- **Описание** — заголовок = название проекта, 5 строк + «Развернуть текст»; пусто — «Добавить описание».
- **«О проекте»**: Тип (гастроль / местное + почему) · **Оценка** (миниатюра + тип, клик — окно оценки) · Состав на
  выезде · Продаётся (Кассир / Яндекс — сколько дат) · Наши площадки (если есть) · Заметка · **Архив** («N прошедших
  дат →» — режим «Архив»).
- **Убрано по решению пользователя:** «Тур в цифрах», список «Площадки», блок «Что изменилось», «Разметка» (перенесена в
  «Редактировать»).

## 3. Страница «Аналитика» (`anPage`; вход — «Аналитика» в шапке проекта, значок «Аналитика» у списка, строка в «Гастролирует»)

### 3.1. Шапка (`.an-hero-m` + классы шапки проекта) — **позиции до пикселя как у страницы проекта**
- ‹ назад — **туда, откуда пришли**: открыли со страницы проекта — на неё (`S.m.anFrom`), иначе — в «Гастролирует»
  (`data-maction="proj-back"`). Справа вверху «В избранное» и **«Проект»** (на страницу проекта).
- Аватар 168 px; название; на месте подзаголовка — **«Аналитика»**; на месте тегов — **пилюля с типом проекта по
  оценке** (`anRatePill`: миниатюра + тип; клик — окно оценки; без оценки — пунктир «не оценён — оценить»).
- На месте ряда кнопок — **разделы**: «Где не были» (стеклянная с текстом; **белая только когда открыта**) и значки
  **Маршрут · Заполняемость · Цены · Площадки** (выбранный — белый). «Организаторы» убраны (решение пользователя).
- **Справа — компактные «стеклянные» плитки 2×2** (150 px): города («нет в N из 98») · даты (мини-столбики по месяцам) ·
  цены · **заполняемость в ср.** (полоска). Правый край — по кнопке «Проект», низ — по ряду кнопок. Плитка
  «заполняемость в ср.» **переворачивается по нажатию** — на обороте **потолок зала** (раздел 6).
- Без фото фон — приглушённая схема России с маршрутом (`anRouteBg`) и затемнение слева.

### 3.2. Разделы (`AN_TABS`, `S.m.anTab`; по одному, переключение не сдвигает экран)
Заголовок раздела — Onest 600, 30 px, отступ 40 px под шапкой (как «Мероприятия»), **без разделительной линии** сверху.
- **Где не были** (`mCandTable`) — города списка, где проекта нет: «по пути», окно дат, конкуренты, лучшая дата, цены.
- **Маршрут** — «Лента | Карта» (`S.m.anMap`).
  - **Лента** (`anTimeline`): города по порядку, точки цветом заполняемости (от 75 % — зелёный, 40–75 % — синий, ниже
    40 % — красный, нет данных — серый; `AN_GOOD`, `AN_LOW`); подписи месяцев, **первый неполный месяц — у левого края**;
    точка — окно даты.
  - **Карта — OpenStreetMap** (Leaflet 1.9.4 с cdnjs и `market-regions.js` грузятся только при открытии; Яндекс Карты
    отклонены — бесплатно нельзя на закрытом сайте). **Масштаб — трекпадом / колесом / пальцами, кнопок «+ / −» нет.**
    Слои (`AN_LAYERS`, `S.m.anLayers`): **Тур** — номера остановок цветом заполняемости, размер — вместимость, стрелки
    направления, клик — окно даты (несколько дат в городе — список); **По пути**; **Архив**; **Организаторы** — цвет
    остановок по организатору; **Конкуренты** — красный круг, мероприятия того же формата в ±7 дней; **Области** —
    закраска по числу дат проекта за сезон (афиша + архив; `MREG`).
  - **Отрезки:** если между соседними датами 2 и более свободных дня (`AN_BREAK_FREE_DAYS`) — перерыв, маршрут режется
    (`anLegs`), линии и стрелок между отрезками нет. **Ползунок «Где тур в день»** шагает по **датам тура** (не по дням
    календаря), перерывы перепрыгивает; жёлтая точка — на городе выбранной даты, подпись «после перерыва N дней»; по
    умолчанию — ближайшая дата от сегодня.
- **Заполняемость** — «По маршруту | Лучшие | Худшие» (`S.m.anSort`); строка — город и площадка, дата, мест, полоса, %,
  вал; клик — окно даты. **Первые 3** (`AN_FEW`), «Показать все · N» / «Скрыть».
- **Цены** — диапазоны «от–до» на общей шкале, первые 3, «Показать все» / «Скрыть».
- **Площадки** (`mRouteVenues(l, 8)`) — площадка, город, тип, мест, дат, заполняемость; первые 8 и «Показать все».
- Убрано: «Карточка проекта», карточки цифр, блок «Продажи» со старым текстом, «Архив», «Все даты», «Лучше / хуже
  всего», подпись шкалы цен, строка «прокатная — N · смешанная — M…», раздел «Организаторы по регионам» (код
  остался, в `AN_TABS` его нет).

## 4. Окна (`pjDialog` — нативный `<dialog>`, Esc и клик мимо закрывают)

### 4.1. Окно даты (`pjOpenDate` / `pjDateHtml`) — вместо правой карточки на этих страницах
- **Первая строка — дата, город и площадка — в одной строке с карандашом и крестиком** (меньше воздуха сверху);
  **после неё разделителя нет**, отступ 24 px. Заголовок окна скрыт (`sr-only`).
- Карандаш — то же редактирование мероприятия (прямой сбор — `openEditor`, рынок — `mEditForm`, в форме есть «Организатор»).
- Блоки через тонкие разделители: заполняемость крупно («занято X из Y · свободно Z» и полоса) · Цены / Вал / Выручка ·
  **Организатор** (пусто, если нет; «вписать / изменить»; пометка «вручную») и «В афише с» · ссылки на кассы **в стиле
  фильтров** (`.fbtn`: «ЯНДЕКС АФИША ↗», «КАССИР ↗», «VLADIMIRKONCERT ↗»).
- Внизу **одна кнопка «Продажи →»**: окно расширяется, справа выезжает панель (`pjdSalesToggle`) — **«Динамика продаж»**
  и **«Распоясовка»** (`hallRows`); прямой сбор — из файлов, рынок — с сервера `/api/sales/detail`. Стрелка → / ←.
- **Убрано по решению пользователя:** тип площадки, «мест в зале», пояснение под полосой, «продажи завышены
  (вопрос 27)», повтор жанра и названия, «Закрыть», «Продажи и зал по рядам».

### 4.2. «Редактировать» (`pjEditHtml` / `pjSave`)
Фото артиста и фон (Загрузить / Заменить / **Положение** — только у фона / Убрать), подзаголовок, описание, состав на
выезде, контакт, телефон, официальный сайт, гонорар, ВКонтакте, Instagram, Telegram, райдеры, другие ссылки, ещё
контакты, заметка; ниже формы — **«Разметка»** (`pjTourHtml`: тип проекта, артист целиком, тип площадки ближайшей даты —

`https://vk.com/x`, `@name` у Telegram / Instagram → полный адрес. Загрузка фото обновляет только превью.

## 5. Оценка проекта — шестиугольник (radar)
- **Где правится:** только [`prototype/project-rating.js`](prototype/project-rating.js) → `PT_CONFIG`: 6 осей (1 Известность,
  2 Широта аудитории, 3 Самопродажа, 4 Отклик на рекламу, 5 Потенциал роста, 6 Ядро фанатов), уровни 0–3 (нет / низкий /
  средний / высокий), **6 эталонов** (Популярный артист [3,3,3,1,1,3], Известный, с рекламой [3,3,1,3,1,2], Нишевый
  [1,1,2,2,1,3], Новый с потенциалом [1,2,1,3,3,1], Слабый проект [2,2,1,1,1,1], Мёртвый проект [1,1,0,0,0,0]) и **порог
  «между»** (`between`: 0,6).
- **Тип не выбирается вручную:** `ptTypeOf` — ближайший эталон по евклидову расстоянию; второй ближе первого меньше чем на
  `between` — «между «X» и «Y»». Рисунок — `ptRadar` (чистый SVG: 3 кольца, оси, номера, закрашенный многоугольник, прошлая
  оценка — пунктиром; цвета от `currentColor` и `--pt-accent` — светлый и тёмный фон).
- **Окно:** слева шестиугольник, тип, дата, легенда; справа 6 переключателей 0–3 с подписями и подсказкой оси — тип и
  шестиугольник **обновляются сразу**; «Сохранить оценку» — когда отмечены все 6 осей.
- **Где видно:** значок в шапке проекта, строка «Оценка» в «О проекте», пилюля в шапке «Аналитики», столбец «Оценка» и
  фильтр «Оценка» (по типу, «Не оценён») в списке «Проекты».
- **Хранение:** `my_projects.json` → `rating: {s, at}`, прошлые — `rating_hist` (до 50). Сервер — `myprojects` «rating».

## 6. Потолок зала (оборот плитки «заполняемость в ср.»)
Какую наибольшую вместимость проект **стабильно** заполняет — главная метрика для подбора площадки. Правило —
`CEIL_CONFIG` в `project-rating.js` (решения пользователя 09.10): выступление «заполнено» — продано **≥ 85 %**; «стабильно» —
хотя бы в **3** разных городах; **потолок** — в каждом городе самый большой заполненный зал, по убыванию, **третий**
(`ptCeiling`). Полоса — потолок / медиана вместимости крупных залов тура (верхняя четверть). **Ручных данных нет.**
Источник — итоги прошедших выступлений (`sales.results` → `sales.export` → `finals` → `MK.finals[ключ проекта]`:
[город, мест в продаже, заполнено %, дата]); на 09.10 — 319 проектов с итогами. Пока «продано» завышено пачками снятых
мест (вопрос 27), потолок тоже может быть завышен. У AdrenalinHouse итогов нет — тестовые цифры с меткой «тест».

| Итоги выступлений (потолок) | база → `sales_snapshot.json.gz` → `finals` | `sales/export.py: finals` |
Прототип, открытый файлом, хранит своё в браузере (`MY_KEY`, `CUR_KEY`); правила повторены в `myApply` / `curLocal` —
**менять вместе с сервером**.
- **Заполняемость даты** (`pjFill`): прямой сбор — схема без брони; рынок — сводка продаж. «Занято» ≠ «продано» —
  пояснение в подсказке.
- **Изменения** (`myDiff`): снимок дат — сравнение по «дата + город + площадка»: новые, снятые, цена, прошедшие. Не видно:
  перенос (= снята + новая), продажи, смена организатора и названия.

## 9. Правила, которые пользователь задал явно (не возвращать)
- Меньше «мусора»: не повторять название проекта; пояснения — в подсказки, не на экран.
- Синие ссылки в тексте не использовать (`.pj-plain`); ссылки на кассы — в стиле фильтров.
- Значки-миниатюры вместо кнопок с текстом, где смысл понятен; подсказка и `aria-label` — обязательно.
- Симметрия: пара значков = ширина и скругление кнопки цены; полоса заполняемости = ширина кнопки цены; плитки
  «Аналитики» — по краю кнопки «Проект»; позиции шапок «Проект» и «Аналитика» совпадают.
- Аналитика (цифры тура, площадки, маршрут, потолок) — на странице «Аналитика», не на странице проекта.
- Кнопка не должна выглядеть нажатой, если раздел не открыт («Где не были»).
