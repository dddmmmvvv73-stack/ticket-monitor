# Свободные даты площадок

Реализовано 05.11.2026 по запросу пользователя. Раздел `#availability` хранит общие ответы площадок, чтобы не прозванивать один город и месяц заново для каждого артиста.

## Работа с разделом

- В меню — **«Свободные даты»**, на телефоне — «Ещё». Переходы также из карточки площадки, рабочего проекта и процесса «Запрос свободных дат у площадок».
- «Города и площадки» выбирает несколько городов / конкретных площадок, первый месяц и горизонт сводки (1 / 3 / 6 / 12 месяцев). Без отдельных площадок берутся все площадки выбранных городов. Выбор городов и площадок сохраняется в браузере.
- **Календарь**: месяц / неделя, прежние стили и компоненты «Работа → Календарь». Нажатие на дату / площадку показывает справа доступность, источник ответа, договорённость и историю. На телефоне панель ниже календаря.
- **По месяцам**: площадки × месяцы, свободные числа, полнота сведений, резервы / брони, дата последнего ответа.
- **Прозвон**: общие запросы или запросы конкретного артиста / рабочего проекта, состояние, дата следующего звонка. Можно сразу создать запросы по всем выбранным площадкам на несколько месяцев; открытые запросы того же артиста и проекта не дублируются.
- Ответ вводится числами и диапазонами: `5, 8, 12–15`. Указываются дата получения ответа, контакт, кто уточнил и комментарий. Залы отдельно не учитываются, уточнения — в комментарии.

## Значение состояний

Полный ответ — **все** свободные даты месяца: остальные дни считаются занятыми; пустой список означает, что свободных дней нет. Частичный ответ меняет только названные свободные / занятые числа. Неизвестные даты остаются «Нет данных». Приоритет у ответа с более поздней датой получения; при равной дате — у последнего внесённого. Для каждой даты частичный ответ дополняет прежний полный, не стирая остальные дни.

Полный ответ закрывает открытые запросы разных артистов за этот месяц, созданные не позже даты ответа. Частичный ответ запросы не закрывает. Ответы неизменяемые: исправление — новый ответ либо «Отменить ошибочный ответ» в истории. При отмене автоматически закрытые им запросы возвращаются в работу.

Наш резерв / подтверждённая бронь принадлежат артисту, при желании — рабочему проекту. На одной площадке в один день допускается одна активная договорённость для всех проектов. Бронь подтверждается **в разговоре**, договор не требуется. Просроченный срок резерва требует уточнения, автоматически дата не освобождается. После снятия договорённости дата требует перепроверки до нового ответа площадки.

«В гастрольный маршрут» открывает существующий редактор с черновиком свободных дат выбранного месяца. Для однозначности — одна выбранная площадка на город; наши резервы и брони в свободные даты не попадают. Сохранение маршрута — прежней кнопкой редактора.

## Хранение и код

- `competitors/availability.py`, GET / POST `/api/availability`; `reports`, `bookings`, `requests`.
- `config/venue_availability.json` — приватный файл, вне git. Создаётся при первой записи; старт без демонстрационных данных. Попадает в существующие зашифрованные копии всего `config/`.
- Площадки и контакты берутся из `venue_book.json`, связь — по `venue` (id справочника). Ответы общие для артистов, договорённости и запросы могут иметь `artist` / `project`.
- Редактирование запросов / договорённостей проверяет `expected`: устаревшая вкладка не затирает новую запись. Сервер проверяет даты, пересечения свободно / занято и конфликт броней.
- Все изменения — в существующем журнале (`availability`); восстановление из журнала также не допускает двойной брони.
- `Design/prototype/availability.js/.css`, общие стили `work-calendar.css` и функции дат `WorkCalendarDates`. В `index.html` выпадающий список переносится внутрь открытого modal dialog, чтобы его пункты оставались доступными для выбора.
