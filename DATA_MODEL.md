## 1. Главные понятия

```
Проект (тур, программа)                 «Юнона и Авось», Театр Рыбникова
  └─ Сеанс (одно выступление)           Ульяновск · Дворец «Губернаторский» · 28.03.2027 19:00
       ├─ Карточки у операторов         Кассир: событие 5887302 · Яндекс: сеанс NzAyfD…
       └─ Запасы билетов (по кассам)    «Эйдж-билет» — общий у Кассира и Яндекса
            └─ Наблюдения (сборы)       04.10 15:50: свободно 1012, по ценам {2200: 64, …}
                 └─ Продажи между сборами  −3 места по 5 500 ₽ …
Площадка → Зал (эталон мест) → Рассадки → Распоясовка сеанса (цены по местам, версиями)
Билетный оператор (реестр) — откуда пришли карточки и наблюдения
```

**Сеанс — главная единица анализа.** Всё считается по сеансу: вал, продажи, процент
от аншлага, итог. Одно и то же выступление у Кассира, Яндекса и vladimirkoncert — один
сеанс с несколькими карточками и запасами.

## 2. Справочники

### 2.1. Билетный оператор
Реестр из TICKET_PLATFORMS.md, раздел 7: `id`, название, сайт(ы), **тип** (региональная
касса / федеральный оператор / витрина-агрегатор), **движок**, регионы и города, что
отдаёт (схема всех мест / только свободные / только остаток; цены; организатор; дата
открытия продаж), ограничения (паузы, частота, антибот), состояние (последний сбор,
ошибки), дата подключения, **польза** (доля мероприятий, видных только у него).
Сейчас: odk33, движок vladimirkoncert (5 сайтов), Кассир, Яндекс Афиша.

### 2.2. Город
Название, федеральный округ, **часовой пояс** (IANA, напр. `Europe/Samara`), номера у
операторов (поддомен и `suburbId` Кассира, `id` города Яндекса), позже — численность
(Росстат). Источник — `config/market.json`, `config/market_kassir_regions.json`,
`market/yandex_cities.json`.

### 2.3. Площадка
Город, **каноническое название**, все написания у операторов (словарь
`market/venue_aliases.json` + сокращения ДК/ККЗ/…), адрес, координаты, **тип** (прокатная /
репертуарный театр / смешанная — ваша разметка), номера у операторов.

### 2.4. Зал, рассадка, места
- **Зал (эталон)** — все кресла зала: зона (уровень), ряд, место, координаты. Эталон —
  самая полная известная схема (обычно схема Яндекса или vladimirkoncert). Место
  опознаётся по ключу **«зона | ряд | место»** (как сейчас в `seatmap.seat_key`), не по
  пикселям.
- **Рассадка** — вариант зала для конкретного мероприятия (с танцполом, без рядов 1–13,
  с приставным рядом): подмножество мест эталона + доп. места. Как сейчас — группа схем,
  совпадающих на ≥ 80% (`seatmap.group_layouts`).
- **Сопоставление мест операторов с эталоном**: место оператора → место эталона по
  нормализованным зоне, ряду, номеру («Литер», «Ложа», «1а» — по словарю). Несопоставленные
  места — с пометкой, в расчёт зала не идут, пока не разобраны.
- **Не кресла** — уровни-услуги вроде «Meet & Greet» (у Яндекса уровни с id 998, 999) —
  исключаются правилом.
- **Танцпол / входные билеты** — сектор без мест: известно только «свободно N»; вместимость
  — если оператор её даёт, иначе неизвестна.
- **Бронь зала** — места, не продающиеся в зале постоянно (авто + ваша ручная), с
  пометкой «бронь или постоянная квота другой кассы» (правило 5 TICKET_PLATFORMS.md).

## 3. Мероприятия и продажи

### 3.1. Проект (тур, программа)
**Постоянный номер** проекта и **несколько написаний** (ключей названия: «Юнона и Авось», «…Рок-опера», «…2027» —
один проект; год и слова «юбилейный», «новый» ключ не меняют); над проектом — **артист / коллектив** (пометку
«гастроль» можно поставить на артиста — для всех его программ на годы вперёд). Ваша пометка привязана к проекту
или артисту, а не к тексту названия; новое похожее название — в очередь подсказок «похоже на размеченный
проект — применить?». Одноимённые постановки разных театров («Щелкунчик») — разные проекты (по театру /
организатору). Ключ проекта (как сейчас `pk`: слова названия без служебных, по алфавиту), название,
формат и ниша, **гастроль / местное** (ваша разметка → разметка площадки → авто, с
причиной; среди авто-признаков — категория Кассира «Гастроли», решение 04.10), организатор(ы). Франшизы с параллельными составами (CAGMO) — один проект, но
маршруты по составам не склеиваются (открытый вопрос).

### 3.2. Сеанс
`id` (наш, постоянный), проект, площадка, зал / рассадка, **дата и время — местные + часовой
пояс города** (в базе — момент времени UTC), **«следим за продажами»** (да — гастроль по разметке проекта /
площадки / авто; нет — местное: сеанс только в афише; с датой включения — чтобы было видно, с какого момента
есть продажи), ниша (сфера / формат / жанр + откуда:
правило / сайт / нейросеть / вручную), возраст, Пушкинская карта, **статус** и история
статусов, дата первого появления, **итог** (3.7).

**Статусы сеанса:** анонсирован → в продаже → распродан → продажи закрыты → прошёл;
отдельно — **отменён**, **перенесён** (тот же сеанс, новая дата; старая дата — в
истории), **снят** (исчез из афиши до даты при нормальном сборе оператора).

### 3.3. Карточка у оператора
Как сеанс выглядит у конкретного оператора: оператор, **внешние номера** (Кассир: карточка
`activity` и сеанс `event`; Яндекс: событие и ключ сеанса; vladimirkoncert: номер сеанса),
ссылка, **название как на сайте**, цены от–до, организатор (у Кассира), дата открытия
продаж (у Яндекса), первое и последнее появление. У одного сеанса — 1…N карточек.

### 3.4. Запас билетов (касса сеанса)
Сеанс × касса: чей запас видим (оператор; у Яндекса — ещё и касса из `sessionServices`),
**общий или поделён** с другими карточками сеанса (группа общего запаса), что известно о
нём (есть ли схема, скрыт ли остаток). Правила 1–3 TICKET_PLATFORMS.md: каждая касса видит
только свой запас; поделённые запасы складываются, общий учитывается один раз.

### 3.4а. Расписание опроса (решение 04.10)
Продажи снимаются только у сеансов «следим за продажами». Как часто — по близости даты: до 7 дней — 3 раза в день,
8–30 дней — раз в день, 31–90 — раз в 3 дня, дальше — раз в неделю. Сначала дешёвый запрос (остаток Кассира, сводка
Яндекса), схема — только если остаток изменился. Свой лимит темпа на оператора: Кассир ограничивает **адрес** после
нескольких сотен запросов подряд (TICKET_PLATFORMS.md, 8.6) — ровный медленный темп в течение суток (~1 запрос в 5–10 с),
«предохранитель» при росте доли ошибок 500, ошибку повторять в следующем сборе. **Кассир — только где без него нельзя:**
сеансы только на Кассире и сеансы с поделённым запасом; при общем запасе Кассира и Яндекса хватает Яндекса (запас
перепроверять раз в неделю).

### 3.5. Наблюдение (один сбор одного запаса)
Время сбора, **свободно всего**, **свободно по ценам** `{цена: штук}`, мест всего (если
оператор даёт), статус продажи, «остаток скрыт», ссылка на сырой ответ в архиве. Если
скачана схема — набор свободных мест (по эталону). Пишется **только при изменении** (иначе —
отметка «проверено, без изменений»). **Каждый изменившийся сырой ответ** (остаток, сводка, схема) — в архив
(решение 04.10).

### 3.6. Продажи
- **Между двумя наблюдениями** (по ценам): `было − стало` по каждой цене → продано штук и
  сумма; отрицательное — возвраты / открытие мест.
- **По местам** (где есть схема): место было свободно → стало занято (продажа, цена — по
  последнему разу, когда оно было свободно) и обратно (возврат / снятие брони).
- **Аномалии — не продажи, пока не подтверждены**:
  - весь зал или почти весь разом стал занят / свободен — сбой сайта или ночное закрытие
    продаж. Пример из истории ЦКиО: 01.10 в 00:42 все 1 099 мест «заняты», записано 701
    «подтверждённая продажа» — это ошибка нынешнего правила;
  - целые ряды / десятки мест разом — снятие квоты, а не продажа;
  - место в корзине (временная бронь) — вернётся через минуты.
  Помеченный интервал в выручку не идёт, пока следующий сбор не подтвердит.

### 3.7. Итог сеанса (на дату выступления)
Фиксируется по последнему сбору до начала и не меняется: мест в зале, выставлено (по
кассам), свободно, **продано за время слежения**, **выручка по подтверждённым продажам**,
**вал** (диапазон + доля мест с точной ценой), **процент от аншлага** («продано /
выставлено в видимых кассах»; если выставленное неизвестно — с пометкой), **полнота** (с какого дня продаж следили, сколько касс
видели из скольких), статус (прошёл / снят / отменён). Это и есть архив года.
**Сделано 06.10:** `sales.results` (каждый час после `db.sync`) пишет `sessions.result` — `st` (прошло / снято до даты),
`cut` (по какой момент), `pools` (по кассе — строка как в сводке продаж: свободно, выставлено, вал, продано и выручка за
слежение), `best` (самая полная касса). Архив для интерфейса — `sales.history` / `/api/archive` (период, город или все).

### 3.8. Распоясовка (цены по местам)
Сеанс × место эталона → цена, **по версиям** (с какого момента действует): цена
появляется, когда место впервые видно свободным; меняется — новая версия (скидка,
подорожание). Цена занятого места, которое ни разу не видели свободным, — оценка по
соседям ряда, с пометкой «оценка». Цены — без сервисного сбора (сбор — отдельно).

### 3.9. Цифры сеанса — определения (решение 04.10)
- **Свободно сейчас** — главная цифра: сколько можно купить сейчас (сумма по кассам, общий запас — один раз). Точно.
- **Выставлено** — свободно + занято в схеме кассы; есть там, где касса даёт полную схему (Кассир со схемой,
  vladimirkoncert). **Мест в зале** — по эталону.
- **Процент от аншлага** — продано / выставлено; где выставленное неизвестно — с пометкой.
- **Вал — как у vladimirkoncert:** выставленные места × цена без сервисного сбора; занятым — цена соседей по ряду;
  всегда с долей точных цен и диапазоном. Кассир без схемы — «вал свободных» + проданное за время слежения; Яндекс без
  Кассира — оценка с диапазоном.
- **Выручка** — по подтверждённым продажам (3.6), с полнотой слежения.

## 4. Правила

1. **Склейка карточек в сеанс:** город + площадка (каноническая, по словарю написаний) +
   местные дата и время + похожее название — то, что уже делает `market.merge_by_slot` и
   соседние правила, плюс vladimirkoncert / odk33 в ту же склейку. Разные залы одной
   площадки в одно время — разные сеансы. Ручная правка склейки — разметкой.
2. **Перенос:** карточка с тем же внешним номером сменила дату или время → тот же сеанс,
   статус «перенесён», старая дата в истории. У Яндекса ключ сеанса содержит время — перенос
   распознаётся по событию + площадке.
3. **«Исчез» ≠ «снят»:** сеанс считается снятым, только если сбор этого оператора прошёл
   нормально (как сейчас защита «меньше половины прошлого сбора» и `GONE_AFTER`).
4. **Время:** у Кассира время местное, хотя помечено `+00:00`; у Яндекса — с поясом;
   у vladimirkoncert — местное. Всё переводится в момент UTC по поясу города; «за N дней до
   начала» и «продажи по часам» считаются в местном времени.
5. **Свободные места Яндекса — по схеме, не по сводке** (пробный сбор 04.10,
   TICKET_PLATFORMS.md, 8.1): сводка складывает кассы, даже если они перепродают один и тот же
   запас («Сергей Орлов» — 468 = 2 × 234), и бывает больше зала (18% сеансов). Сводка — чтобы
   найти сеанс и список касс; запас — уникальные свободные места схемы.
6. **Сырые ответы — в архив** (Object Storage), в базе — только разобранное и ссылка на
   сырьё. Хранить **каждую изменившуюся сводку и схему** (решение 04.10).
7. **Точность — у каждой цифры**: вал — диапазон и доля точных цен; выручка — полнота
   слежения и число видимых касс (QUESTIONS.md, вопрос 22).

## 5. Ваша разметка и ручные правки

местное), тип площадки, правки сеансов, свои мероприятия, ниша по названию, ручная бронь
рядов, фильтры разделов. Хранится с датой правки; собранное никогда её не перезаписывает.
