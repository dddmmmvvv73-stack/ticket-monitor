## 1. Что хочет пользователь (его слова, 26.10)

1. **Один фильтр:** города, где артист не был и где сейчас не стоит.
2. **Карточка города:** открываю город, вношу все данные финмодели и отмечаю его: **подходит / на рассмотрении / не подходит**.
   Отмеченные попадают в **отдельный список**. Из него я формирую предложение артисту и документ для руководителя.
3. **Связь с «Турами» убрать из подбора.** «Туры» — отдельная, штучная работа: города, порядок и артист уже известны,
   остаётся прозвонить площадки. Массовый перенос из подбора там лишний.
4. **Таблица — как в других вкладках:** выбор столбцов (добавить / убрать), порядок, ширина. По умолчанию — только нужное.
   Сейчас слишком много текста и фильтров, которые не помогают работе.
5. **«По пути» в подборе не нужен** — ни в деньгах, ни в таблице: «не вижу в этой функции для этой вкладки смысла».
6. **Руководителю — и ссылка с комментариями, и PDF.**

## 2. Как должно стать

### 2.1. Экран артиста — две вкладки
Над таблицей переключатель **«Все города · N» | «Предложение · M»**.

- **«Все города»** — подбор: таблица кандидатов.
- **«Предложение»** — города со статусом «подходит» или «на рассмотрении». Это отдельный список с документами (п. 2.5).

### 2.2. Шапка — минимум
- Строка списка без изменений: «Список ▾», «+ Новый список», «Изменить список», «Удалить».
- **Экономика артиста — одна строка:** Гонорар · % сверху · Состав · Заполняемость (50/70/90).
  Кнопка **«Ещё ▾»** раскрывает остальное: райдер, суточные, реклама, московские, РАО, кассы, уровень цен, зал от–до,
  формат. **По умолчанию:** «Ещё» свёрнуто и запоминается в браузере (`PL_PREFS`).
- **Убрать длинные тексты:**
  - подзаголовок экономики;
  - абзац «Как считается…»: заменить значком «?» с подсказкой «Как считается — CITY_PICK.md»;
  - строку «N городов по нашей базе · свободных…»;
  - подпись «окупается — запас от +10 %…»;
  - сноску под таблицей про логистику и 40 %.

  Числа оставить там, где они нужны: в счётчиках вкладок и фильтра.

### 2.3. Фильтры подбора — только эти
| Фильтр | Как работает |
|---|---|
| **«Не были и не стоят»** | переключатель, включён по умолчанию. Показывает только статус `free` из `tbAnalyze`. Выключен — показываются все города, у занятых статус виден в столбце «Статус» |
| **Окупаемость** | выпадающий список: все / окупается / на грани / не окупается / нет данных. **По умолчанию:** «все» |
| **Поиск города** | поле, фильтрует по названию |
| **Области** | оставить существующую кнопку со списком |
| **Столбцы** | значок, п. 2.4 |

**Убрать из режима подбора:**
- «Свободные / Все города» (заменён переключателем);
- «Жителей от–до»;
- «До гастролей»;
- «Трансфер / Поезд / Авиа»;
- «+ все города от 20 тыс.»;
- сегмент «Можно везти / Все / …»;
- **«по пути»** (решение пользователя 26.10, п. 1.5): зелёную строку «по пути: …» под городом, «ближайший город
  гастролей», сортировку «ближе к гастролям». Дорога считается как сейчас — из Москвы, по `PICK_DEFAULTS.travel`;
- флажки выбора строк;
- плавающую панель «Выбрано… Создать тур».

В режиме **без гонорара** (старый список продюсера) экран не менять.

### 2.4. Таблица — общая система столбцов
Сейчас система столбцов есть только у таблицы тура:
- описание столбцов `PL_TCOLS`;
- `plColOn`, `plColW`, `plColsOrdered`, `plFitLabel`, `plColsControl`;
- перетаскивание заголовка `[data-plcolhead]`, ширина `[data-plresize]`;
- настройки в `PL_PREFS.vis / .w / .order`.

**Обобщить её** на набор столбцов и ключ настроек, например `plCols(set)`, где `set = { cols, prefs: "tcols" | "pkcols" }`.
Таблица тура должна работать **как раньше**, а её сохранённые настройки — не потеряться: миграция `PL_PREFS.vis` →
`PL_PREFS.tcols.vis`. Подбору — свой набор `PK_COLS` и свои настройки.

### 2.5. Карточка города — вся финмодель и решение
Открывается кликом по городу (сейчас `tbOpenCard`). Сверху — три кнопки решения:
**Подходит · На рассмотрении · Не подходит**. Повторный клик снимает решение.

**Поля по группам:**

| Группа | Поля |
|---|---|
| **Зал и билеты** | зал (выбор из залов города), мест, средняя цена билета, заполняемость. **Распоясовка** — по желанию, как в карточке строки тура: пояса «название · цена · билетов · заполняемость», шаблон поясов площадки из «Площадок». Переиспользовать вёрстку и формулы (`planCalc` уже умеет `zones`) |
| **Артист в этом городе** | гонорар, % сверху, суточные, состав, авторские. Пусто — из экономики артиста (серым); правка — только для города |
| **Расходы города** | райдер одной суммой **или** «Расписать по статьям»: 8 статей финмодели `PLAN_ORG` (трансфер, проживание, технический райдер, кейтеринг, грузчики, охрана, службы, прочие). Если заполнена хоть одна статья, их сумма заменяет райдер. Ещё: аренда, реклама, дорога |
| **Проценты** | комиссия касс, агентские, РАО |
| **Заметка** | текст (контакт площадки, условия) |

**Ниже полей:**
- расшифровка от вала до прибыли (есть);
- сценарии 50 / 70 / 90 (есть);
- «Откуда цена» и «Крупные концерты» — **свёрнуто** по умолчанию.

У каждого поля:
- источник серым в подсказке, а не отдельным столбцом текста;
- ↺ — вернуть расчётное значение.

Все правки сохраняются в `lists[id].cities[город]`.

### 2.6. Вкладка «Предложение»
- Таблица того же вида и с той же системой столбцов (свой ключ настроек `PL_PREFS.ofcols`).
- Города: **подходит**, затем **на рассмотрении** — двумя группами с подзаголовками.
- **Порядок** внутри группы — перетаскиванием строки (как в туре, `plMoveRow`). Хранится в `cities[город].ord`.
- **Итог сверху** одной строкой: городов, сборы, расходы, прибыль. Считать только «подходит»; переключатель «+ на рассмотрении».
- **Кнопки:**
  - **«Предложение артисту (PDF)»**: только «подходит», по умолчанию; флажок «включить на рассмотрении»;
  - **«На согласование (PDF)»**: «подходит» и «на рассмотрении» с пометкой статуса;
  - **«Ссылка для руководителя»**: то же содержание, что в PDF «На согласование», но страницей с комментариями (п. 2.8).

  Генерацию документов взять из `tbOfferDoc`, источник строк — этот список, а не видимая таблица подбора.
- «Не подходит» в предложение не попадает. Такие города остаются в «Всех городах»: при включённом «Не были и не стоят»
  видны с решением «не подходит». **По умолчанию:** скрывать их флажком «скрыть не подходящие», включённым.

### 2.7. Связь с «Турами» — убрать из подбора
- Удалить кнопку «Тур в финмодель» (`tb-otour`), флажки строк и «Создать тур из выбранных» (`tb-tour`) **в режиме подбора**.
- **По умолчанию:** функцию `tbMakeTour` не удалять, оставить без кнопки. В режиме без гонорара (список продюсера)
  «Создать тур из выбранных» работает как раньше.

### 2.8. Ссылка для руководителя с комментариями (решение пользователя 26.10, п. 1.6)

**Как пользуется организатор:**
1. Во вкладке «Предложение» нажимает **«Ссылка для руководителя»**.
2. Сайт сохраняет **снимок** предложения на этот момент: города, цифры, допущения. Это версия от такого-то числа и
   времени; дальнейшие правки в подборе её не меняют.
3. Сайт показывает адрес и кнопку **«Скопировать»**. Организатор отправляет адрес руководителю в мессенджере.
4. Повторное нажатие после правок создаёт **новую версию**. У старой ссылки сверху появляется пометка «есть более
   новая версия» со ссылкой на неё.
5. Комментарии руководителя видны во вкладке «Предложение»:
   - у города — значок с числом комментариев и решением руководителя;
   - сверху — счётчик «новых N».
6. Есть кнопка **«Закрыть ссылку»**: после неё страница отвечает «ссылка закрыта».

**Что видит руководитель** — страница без входа, без меню сайта, на телефоне без прокрутки вбок:
- шапка: артист, период, дата версии;
- итоги и допущения — как в PDF «На согласование» (`tbOfferDoc`, kind `boss`);
- таблица городов как в PDF. У каждого города:
  - кнопки **«Согласовано» / «Вопрос» / «Не согласовано»**;
  - поле комментария;
- общий комментарий внизу;
- поле «Ваше имя» один раз, запоминается в его браузере (`localStorage`);
- кнопка «Скачать PDF» — печать этой страницы.

Комментарии и решения сохраняются сразу. Руководитель видит свои и чужие с именем и временем.

**Устройство:**
- **Хранение:** `config/shares/<token>.json` — `{token, list, title, created, closed, prev, next, snapshot: {…},
  comments: [{city | "", name, text, decision, at}]}`.
  - `token` — 22 случайных символа (`secrets.token_urlsafe(16)`).
  - Папка `config/` попадает в часовую закрытую копию (`db/offsite.py --config`), поэтому комментарии не потеряются.
  - `config/shares/` добавить в `.gitignore`: репозиторий **публичный**, а там гонорары.
- **Отдельное маленькое приложение `share_app.py`** на своём порту (**5070**; 5060 из первой версии плана браузеры не открывают — это порт SIP, проверено 26.10), только два адреса:
  - `GET /s/<token>` — страница;
  - `POST /s/<token>/comment` — запись комментария. Проверки: длина до 2 000 знаков, имя до 80, не больше
    60 записей в минуту на одну ссылку.

  Больше ничего в этом приложении нет: ни `/proto/`, ни `/api/`. Так снаружи виден **только этот порт**, а сам сайт
  остаётся закрытым. Страница отдаётся с `X-Robots-Tag: noindex` и `Referrer-Policy: no-referrer`.
- **В основном сайте** (`app.py` / `competitors/market_api.py`):
  - `POST /api/shares` — создать снимок из списка;
  - `GET /api/shares?list=` — версии и комментарии;
  - `POST /api/shares/<token>/close` — закрыть ссылку.
- **Снимок** строит браузер организатора: те же строки и цифры, что идут в PDF (`tbOfferDoc`). Сервер только проверяет
  размер (до 1 МБ) и сохраняет.
- **Запуск:** `deploy/laptop/install.sh` — новая служба launchd `ru.ticketmonitor.share` (`tm.sh share`, всегда включена,
  как `web`).

**Доступ снаружи — нужно действие пользователя:**
- Руководитель не в нашей сети, поэтому нужен публичный адрес только для порта 5070.
- **По умолчанию — Tailscale Funnel.** Tailscale и так запланирован для доступа с телефона (PROJECTS.md):
  - пользователь ставит Tailscale на Mac и входит;

  - затем исполнитель запускает `tailscale funnel --bg 5070`;
  - адрес будет вида `https://<имя-mac>.<сеть>.ts.net/s/<token>`; базовый адрес хранить в настройке сайта.
- **Риск:** 20.10 Cloudflare не подключился из-за VPN Happ (PROJECTS.md). Tailscale — тоже VPN; проверить совместную работу
  при установке. Не получится — доложить пользователю, обход не придумывать.
- **Ноутбук должен быть включён:** иначе ссылка не открывается. Об этом — подсказка у кнопки.

  «Ссылка откроется только на этом компьютере, пока не настроен внешний доступ». PDF работает всегда.

## 4. Этапы и проверка

Каждый этап — отдельный коммит, тесты зелёные, проверка Playwright на копии (порт 5051).

|---|---|---|

| 2 | Таблица подбора на новой системе + сортировка по клику + фильтры п. 2.3 + убрать тексты п. 2.2 | по умолчанию 7 столбцов; «Столбцы» добавляют и убирают; на 390 px нет прокрутки страницы вбок (таблица прокручивается внутри карточки) |
