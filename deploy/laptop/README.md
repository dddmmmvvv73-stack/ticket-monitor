# Ноутбук как временный сервер (с 12.10.2026)

**Почему.** 11.10 в 04:00 у Yandex Cloud авария (питание зон ru-central1-a и -b) — наш сервер недоступен, срок восстановления
неизвестен. Платить второму провайдеру пользователь пока не готов — сервером временно стал ноутбук (решение 12.10).

## Как устроено
- **Отдельная копия проекта — `~/tm-server`** (как `/opt/ticket-monitor` на сервере): клон GitHub + свои `data/` и `config/`.
  Рабочая копия для разработки — `~/Desktop/Parser/ticket_monitor` (в «Рабочий стол» фоновым службам macOS доступа нет).
  Правки кода — в рабочей копии → `git push` → `~/tm-server` подтягивает сам перед сборами (`collect`, `market`, `sync`).
- **Расписание — launchd** (`deploy/laptop/install.sh`), дела — `deploy/laptop/tm.sh`:

  | Дело | Когда | Что |
  |---|---|---|
  | web | всегда | сайт **http://127.0.0.1:5050/proto/** (только на этом ноутбуке) |
  | collect | :25 каждый час | площадки прямого сбора |
  | sales | :05 каждый час | продажи Кассира (лимит 500 в сутки) и Qtickets (ступенями), сводка |
  | sync | :58 каждый час | пополнение базы, итоги сеансов |
  | market | 21:00 | афиша рынка: Кассир + Qtickets, 344 города |
  | backup | 03:30 | зашифрованная копия в закрытый репозиторий `ticket-monitor-backup`: база и данные — своя ветка `day-ГГГГ-ММ-ДД` (последние 7), снимки настроек по дням и месяцам — ветка main |
  | backupcfg | каждые 15 мин | только `config/` (площадки, финмодель, проекты, фото, журнал изменений) — если изменились; ветка `config` |
  | check | 1-го числа, 04:30 | пробное восстановление: скачать копию с GitHub, расшифровать, сверить с живыми данными |
  | awake | всегда | не засыпать, пока ноутбук на питании (`caffeinate -s`) |
- **Яндекс** — с 13.10 собирается и с ноутбука (решение пользователя: отказ 06.10 закрыл только облачный сервер; проверка
  13.10 с ноутбука — страница, сводка, антибот, схема мест и афиша — все ответы 200). Продажи — `SALES_BUDGET_YANDEX=2500`
  запросов в сутки (≈ 350–500 снимков сеансов), афиша — раз в сутки в 21:00. До 13.10 был выключен (`TM_DISABLED_OPERATORS`).
- **База** — локальный PostgreSQL (`~/tm-server/data/pgdata`, пакет pgserver). История продаж с ноутбука — с 12.10;
  история сервера (04–11.10) — на сервере и в его ночной копии; объединить, когда сервер вернётся.

## Управление
- Журналы: `~/tm-server/data/logs/<дело>.log`; афиша рынка — `~/tm-server/data/competitors/market/market.log`.
- Запустить дело сейчас: `launchctl kickstart gui/$(id -u)/ru.ticketmonitor.<дело>` (или «Собрать сейчас» на сайте).
- Состояние: `launchctl list | grep ticketmonitor`; здоровье: `curl -s 127.0.0.1:5050/health`.
- Убрать расписание: `bash ~/tm-server/deploy/laptop/install.sh remove`; поставить снова — без `remove`.
- **Ноутбук должен быть включён и на питании.** С закрытой крышкой без внешнего экрана Mac всё равно засыпает —
  сборы пропускаются (launchd догонит пропущенное после пробуждения одним запуском).

## Уведомления и доступ с телефона
- **Telegram** — сбой копии или проверки восстановления → сообщение. Настройка: бот у @BotFather → написать ему /start →
  `cd ~/tm-server && python3 -m competitors.telegram setup`.
- **С телефона** — Tailscale (бесплатная личная сеть: сайт виден только вашим устройствам): приложение на Mac и телефоне,
  один вход; затем `tailscale serve --bg http://127.0.0.1:5050` — адрес вида `https://<имя-mac>.<сеть>.ts.net/proto/`.

## Журнал изменений
Каждая правка на сайте — `config/history/changes-ГГГГ-ММ.jsonl` («было → стало»), вернуть — «Настройки → Журнал изменений».

## Копия (db/offsite.py)
- Каждую ночь: база (`pg_dump`) + `data/competitors` + `config/` → `openssl aes-256-cbc` → `ticket-monitor-backup`
  (закрытый). Каждая копия — **своя ветка `day-ГГГГ-ММ-ДД`**, хранятся последние 7; ночью уходит только новая (~80 МБ),
  ветки старше удаляются. Ветка main — инструкция и снимки настроек. Первая копия — 12.10 (59,7 МБ), расшифровка проверена.
- **23.10 — почему по веткам:** до этого все 7 копий каждую ночь заново уходили одним коммитом в main; 22.10 отправка
  перевалила за 500 МБ (буфер git `http.postBuffer`), git перешёл на передачу частями, GitHub ответил `HTTP 400` —
  22 и 23.10 копии в GitHub не ушли (на ноутбуке были целы). Telegram-бот не настроен — сбой заметили только в сессии.
- **Пароль** — в Связке ключей macOS, служба «ticket-monitor-backup»:
  `security find-generic-password -s ticket-monitor-backup -w`. **Сохранить у себя отдельно** — без него копия бесполезна.
- Восстановление — README в репозитории копий.

## Когда Яндекс-сервер вернётся
Сервер сам включит свои сборы по таймерам — **два компьютера начнут собирать одни и те же кассы с двух адресов**.
Так нельзя (двойная нагрузка; одну кассу — с одного адреса). Сторож на GitHub закроет issue «Сервер: …» — письмо.
Сразу после этого:
1. Решить, кто главный: сервер (сайт доступен отовсюду) или ноутбук.
2. На втором — остановить сборы (`install.sh remove` на ноутбуке или `systemctl disable --now tm-*.timer` на сервере).
3. Объединить историю продаж: снимки ноутбука с 12.10 → в базу главного (ключи сеансов те же).
4. Копию вне Яндекса оставить в любом случае: ночная копия сервера — тоже в `ticket-monitor-backup` (или скачивать
   на ноутбук).
